# **이벤트 버스**
- ### **발행-구독(Publish-Subscribe) 구조를 중앙 통로로 묶어, 이벤트를 발생 시키는 발행자와 반응하는 구독자가 서로를 직접 할지 못하게 분리해 결합도를 낮추는 설계 패턴**
- ### **플레이어 체력 감소, 아이템 획득, 주문 완료 같은 이벤트를 버스에 던지고, 관련 있는 대상들이 이를 받아 처리하는 '중앙 중계 역할'** 
- ### **전투 시스템이 UI나 사운드 시스템의 참조를 직접 갖고 있지 않아도 되므로 새 구독자를 추가할 때 기존 코드를 덜 수정하는 '느슨한 결합'**
- ### **이벤트가 많아지면 이벤트의 흐릅을 추적하기 어려워질 수 있고 구독 해재를 빠뜨리면 메모리 누수나 중복 실행이 생길 수 있음** 

# **try** 
- ### **예외(Exception)가 발생할 수 있는 코드를 감싸는 블록을 시작하는 키워드, 단독으로 쓰지 않고 catch나 finally와 함께 쓰임**
- ### **파일 읽기, 네트워크 요청, 형변환(int.Parse)처럼 실행 중 오류가 날 수 있는 코드를 try 안에 넣음**
- ### **try블록 안에서 예외가 발생시 남은 줄을 건너뛰고 catch 또는 finally블록 으로 넘어감**
- ### **정상 실행 시 예외가 없으면 try 블록을 끝까지 실행하고 catch, finally는 건너뜀**
